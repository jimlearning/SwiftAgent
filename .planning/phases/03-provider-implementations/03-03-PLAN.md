      - "gpt-5.2": contextWindow 128000, maxOutputTokens 16384, supportsThinking false, supportsToolUse true
      - "gpt-5.2-mini": contextWindow 128000, maxOutputTokens 4096, supportsThinking false, supportsToolUse true
      - "o4": contextWindow 200000, maxOutputTokens 32768, supportsThinking true, supportsToolUse true

    - `public var model: any LanguageModel { self }`
    - `public func respond(to: Transcript, tools: [RuntimeToolDefinition], options: GenerationOptions, streamingInto: GenerationChannel) async throws`
      - Translate transcript via OpenAITranscriptTranslator.translate()
      - Translate tools via OpenAIToolTranslator.translate()
      - Build URLRequest: POST `{baseURL}/v1/chat/completions`, headers: `Authorization: Bearer {apiKey}`, `Content-Type: application/json`
      - Body dict: `["model": modelID, "messages": messages, "stream": true, "stream_options": ["include_usage": true]]`
      - If tools array non-empty: `["tools": tools, "tool_choice": "auto"]`
      - If options.maxTokens: `["max_completion_tokens": options.maxTokens!]`
      - If o4 model AND options.reasoningBudget: `["reasoning_effort": mapBudgetToEffort(options.reasoningBudget!)]` — mapping: nil→nil, 0-4096→"low", 4097-16384→"medium", 16385+→"high"
      - If options.temperature AND not o4: `["temperature": options.temperature!]` — o4 does not support temperature
      - Execute `session.bytes(for: request)`, check status code, pass `bytes.lines` to OpenAISSEParser
      - OpenAISSEParser parses SSE chunks and calls channel methods

    **File 2: OpenAITranscriptTranslator.swift** — `struct OpenAITranscriptTranslator` (internal, Sendable)
    - Single static method: `static func translate(_ transcript: Transcript, systemPrompt: String?) -> [[String: Any]]`
    - Translation table (RESEARCH.md Pattern 2 OpenAI example):
      - .instruction(String) → `{role: "system", content: String}` — ONE system message at the start of the array. If multiple .instruction entries, concatenate with "\n\n". If systemPrompt is also provided, prepend it.
      - .prompt(String) → `{role: "user", content: String}`
      - .response(String) → `{role: "assistant", content: String}`
      - .toolCall(id, name, input: Data) → `{role: "assistant", tool_calls: [{id: String(id), type: "function", function: {name: String(name), arguments: String(decodedInput)} }]}`. Use `String(data: input, encoding: .utf8) ?? "{}"` for arguments.
      - .toolOutput(id, output, isError) → `{role: "tool", tool_call_id: String(id), content: String(output)}`
      - .thinking(String) → For non-o4 models: `{role: "assistant", content: "[Thinking] \(text)"}`. For o4 models: thinking content is NOT included in messages (OpenAI rejects thinking in message history). This is a provider-level decision — the modelID is not available to the translator, so always use the "[Thinking]" text prefix approach for now.
      - .system(String) → `{role: "user", content: "[System] \(text)"}`
    - Unlike AnthropicTranscriptTranslator, OpenAI uses flat message array (one message per entry), not role-flushing with multi-block messages. Each non-instruction entry maps to exactly one message in the output array.

    **File 3: OpenAIToolTranslator.swift** — `struct OpenAIToolTranslator` (internal, Sendable)
    - Single static method: `static func translate(_ tools: [RuntimeToolDefinition]) -> [[String: Any]]`
    - OpenAI function-calling format: `{type: "function", function: {name: tool.name, description: tool.description, parameters: <JSONSchema>}}`
    - JSONSchema→parameters mapping: `type` → `"type"`, `properties` → `"properties"` dict, `required` → `"required"` array. Handle nested object/array schemas recursively.
    - OpenAI-specific: `strict: true` on function definition for models that support it. `additionalProperties: false` unless schema explicitly allows.
    - If tools array is empty, return empty array (not `nil` — OpenAI API treats empty tools array as "no tools")

    **File 4: OpenAISSEParser.swift** — internal actor for SSE parsing
    - `func parse(lines: AsyncThrowingStream<String, Error>, channel: GenerationChannel) async`
    - SSE event dispatch:
      - Each line starting with `data: ` is a JSON chunk
      - Skip `data: [DONE]` — stream end sentinel
      - Parse JSON: `choices[0].delta.content` → text delta: accumulate + emit textDelta snapshot
      - Parse JSON: `choices[0].delta.reasoning_content` (o4 models): accumulate + emit thinkingDelta snapshot
      - Parse JSON: `choices[0].delta.tool_calls` — multi-chunk accumulation per RESEARCH.md Pitfall 4:
        - Maintain `private var toolCallAccumulators: [Int: ToolCallAccumulator]` keyed by `tool_calls[].index`
        - ToolCallAccumulator tracks: `id: String?`, `name: String?`, `argumentsBuffer: String`
        - On each chunk with `tool_calls`: for each tool_call in the array, update the accumulator at its index
        - If `function.name` is present: set accumulator.name
        - If `function.arguments` is present: append to accumulator.argumentsBuffer
        - If `id` is present: set accumulator.id
      - Parse JSON: `choices[0].finish_reason`:
        - If `"stop"`: finalize any pending tool calls, then `channel.complete(stopReason: "end_turn", usage: parsedUsage)`
        - If `"tool_calls"`: finalize all tool call accumulators → emit `toolCallRequested` for each, then `channel.complete(stopReason: "tool_use", usage: parsedUsage)`
        - If `"length"`: `channel.complete(stopReason: "max_tokens", usage: parsedUsage)`
      - Parse JSON: `usage` at top level (when `stream_options.include_usage` is true): extract `prompt_tokens`, `completion_tokens`, `total_tokens` → map to Usage struct
      - Unknown keys/fields: silently ignore
    - Tool call finalization: when finish_reason triggers or arguments JSON parses as valid complete JSON, call `JSONSerialization.jsonObject(with: argumentsData)` to validate. If parseable, emit `channel.send(toolCallRequest: id, name: name, input: argumentsData)`. If unparseable and finish_reason is received, emit with raw arguments string anyway.
    - Snapshot semantics REQUIRED: accumulatedText and accumulatedThinking are full strings sent each emission.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AgentRuntime → OpenAIProvider API | Untrusted HTTP responses — SSE chunks validated before SessionEvent emission |
| OpenAIProvider → api.openai.com | API key crosses boundary in Authorization header. TLS via URLSession. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Spoofing | OpenAISSEParser | mitigate | Parse only lines with `data: ` prefix. Validate JSON structure before interpreting delta keys. Unknown delta fields silently ignored. `[DONE]` sentinel handled explicitly. |
| T-03-13 | Tampering | OpenAISSEParser | mitigate | Multi-chunk tool call arguments validated via JSONSerialization before emission. Malformed arguments at finish_reason still emitted (model error, not parser error). |
| T-03-14 | Information Disclosure | OpenAIProvider | mitigate | API key stored as `private let`. Debug logging masks key values. Error messages do not include raw API responses. |
| T-03-15 | Denial of Service | OpenAISSEParser | mitigate | Tool call accumulator dictionary bounded by tool_calls index (model-controlled, typically 1-5). Malformed chunks caught by try? — parser continues. |
| T-03-16 | Elevation of Privilege | OpenAIProvider | mitigate | Tool calls emitted as SessionEvent.toolCallRequested — actual execution gated by AgentRuntime's permission check in the agent loop. Provider has no execution authority. |
| T-03-SC | Tampering | Package installs | accept | Zero external packages. All dependencies system-provided. |
</threat_model>
