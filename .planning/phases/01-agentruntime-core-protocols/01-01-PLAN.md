<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AgentRuntimeError ↔ consumer | Error cases carry structured data (e.g., `unauthorized(reason:)`). No API keys in error messages per ASVS V7. |
| AgentPermission ↔ PermissionEngine | Permission enum defines access control taxonomy. `PermissionEngine.check()` is the single gate per ASVS V4. |
| GenerationChannel ↔ executor | Channel receives structured events. Tool input/output crosses this boundary as `Data` (Codable-encoded). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | AgentRuntimeError | mitigate | `.unauthorized(reason:)` carries a reason string, never an API key. Plan 01 action specifies `reason: String` not `rawResponse: String`. |
| T-01-02 | Information Disclosure | Transcript.Entry.toolCall | mitigate | Tool input stored as `Data` (opaque), not `any Codable`. Consumers must explicitly decode with known types. |
| T-01-03 | Elevation of Privilege | AgentPermission | mitigate | `CaseIterable` conformance enables exhaustive switches. `PermissionEngine.check()` is the single gate — no backdoor permission checks. |
| T-01-04 | Tampering | GenerationChannel | accept | Channel is a protocol definition only — no runtime data flow in Phase 1. Implementation (Phase 2) will use actor isolation for continuation access. |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | Phase 1 adds zero external packages (pure Swift stdlib + Foundation). No supply-chain risk. |
</threat_model>
