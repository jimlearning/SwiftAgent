<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LanguageModel.makeExecutor() → executor | Factory boundary: model creates executor. Executor must not leak model credentials. |
| LanguageModelExecutor.respond() → GenerationChannel | Executor pushes typed events into channel. Channel is the trust boundary between provider internals and runtime. |
| MemoryStore ↔ consumer | Generic methods `store<T>/retrieve<T>` accept arbitrary Codable+Sendable types. `value: Data` in MemoryEntry is opaque. |
| ToolMetadata.permissionCategory → PermissionEngine | ToolMetadata declares permission category. Actual enforcement is in PermissionEngine.check(). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Elevation of Privilege | ToolMetadata.isEnabled | mitigate | `isEnabled` defaults to `true` but is controlled by ToolEngine registration (not settable by model). Metadata is read-only at tool execution time. |
| T-01-06 | Information Disclosure | LanguageModelCapabilities | mitigate | `providerDisplayName` is display-only, never carries API keys. API keys live in executor implementation (Phase 3), not in the protocol. |
| T-01-07 | Tampering | MemoryStore.retrieve<T> | accept | Generic retrieval with type parameter `T` — the caller specifies the expected type. If wrong type is specified, decoding fails at runtime. Mitigation in Phase 3: SQLiteMemoryStore validates schema. |
| T-01-08 | Denial of Service | GenerationOptions.maxTokens | accept | `maxTokens` is an optional config value; no enforcement at protocol level. Implementation (Phase 3 executor) must enforce reasonable bounds per provider capabilities. |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | Phase 1 adds zero external packages. No supply-chain risk. |
</threat_model>
