  <action>
    DefaultToolEngine.execute() currently returns a hardcoded stub string `"[Phase 2 stub] tool \(name) executed with ..."` (SubsystemStubs.swift line 49). The type-safe execution path was deferred to Phase 3, which is now complete. Replace the stub with real tool execution.

    Implementation approach — type-erased execute closure stored at registration time:

    1. Replace the registry value type from `(tool: any RuntimeAgentTool, metadata: ToolMetadata)` to a struct `RegistryEntry` that adds an `execute: @Sendable (Data) async throws -> ToolOutputValue` closure.

    2. Define `RegistryEntry` as a private struct inside DefaultToolEngine:
       - `let tool: any RuntimeAgentTool` — for getDefinition/getAllDefinitions
       - `let metadata: ToolMetadata` — for future metadata queries
       - `let execute: @Sendable (Data) async throws -> ToolOutputValue` — the type-erased runner

    3. Create a private generic helper `_register<T: RuntimeAgentTool>(tool: T, metadata: ToolMetadata)` that opens the existential:
       - Creates a RegistryEntry with the tool and metadata
       - The execute closure captures `tool` (value type or reference) and does `JSONDecoder().decode(T.Arguments.self, from: data)` followed by `try await tool.call(arguments: decodedInput)`
       - Stores the RegistryEntry in the `registry` dictionary keyed by `tool.name`

    4. Change the public `register(tool: any RuntimeAgentTool, metadata: ToolMetadata) async` to call `_register(tool: tool, metadata: metadata)` — Swift's type system opens the existential automatically when passing to a generic function.

    5. Replace the stub `execute(name:input:)` implementation with:
       - Look up `registry[name]`
       - If nil: `throw AgentRuntimeError.toolNotFound(name: name)`
       - If found: `return try await entry.execute(input)`

    6. Update getDefinition and getAllDefinitions to access `entry.tool` (via the new struct) instead of `entry.0` (the old tuple).

    7. Update the doc comment on execute() — remove "In Phase 2 this returns a canned string stub" and "The type-safe execution path arrives in Phase 3."

    8. Delete the `Stub output` comment.

    Design rationale: This avoids changing the ToolEngine protocol signature (remains `any RuntimeAgentTool`). The existential is opened at the registration boundary via Swift's generic function dispatch. Each tool's concrete Arguments type is captured in the execute closure at registration time. This is the standard Swift pattern for type-erased heterogenous collections of PATs with associated types.
  </action>
